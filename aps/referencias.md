## Como citar no corpo do item

- Chamada no texto pelo sistema autor-data, com a letra da Parte A quando o autor tem mais de uma obra na mesma data: (NGINX, [20--]f), (FIELDING; NOTTINGHAM; RESCHKE, 2022b).
- Página sem data de publicação: `[20--]`. Norma viva, como o Fetch Standard: data de atualização exibida na página no dia do acesso.
- Toda referência on-line leva "Disponível em:" e "Acesso em:" com a data em que o autor consultou a página.
- Quem citar uma referência da Parte B a move para a Parte A no PR do próprio item e preenche a data de acesso.

### Observações da conferência

- **ISO/IEC/IEEE 42010: edição de 2022.** O esboço usa o título da edição de 2011 (*Systems and software engineering – Architecture description*), que a página da ISO marca como retirada. A edição vigente é a 42010:2022 (2. ed., nov. 2022, 62 p.), com o título *Software, systems and enterprise — Architecture description*. A entrada segue a forma usada no item 2.2. As cláusulas 5.2.12 e 6.10 vêm do registro de verificação do próprio item 2.2; esta lista confere só os dados bibliográficos, e a conferência das cláusulas fica com o G7.

- **TLS 1.3: RFC 9846 no lugar da RFC 8446.** O esboço cita a RFC 8446 (2018). A página da RFC 8446 no RFC Editor informa que ela foi tornada obsoleta pela RFC 9846 (jul. 2026), que mantém o mesmo protocolo (TLS 1.3, mesmo número de versão, compatível com a anterior). Conferido de novo na página da RFC 9846 no RFC Editor em 17/11/2026 ("This document obsoletes RFC 8446"). Os itens 1.3 e 2.1 passaram a citar a RFC 9846; a 8446 aparece só no 1.3, como versão anterior. Os itens 1.4 e 2.8, se citarem o TLS, usam a 9846.
- **Nginx e TLS 1.3.** A página *Configuring HTTPS servers* informa que, a partir da versão 1.27.3, o padrão do Nginx é `ssl_protocols TLSv1.2 TLSv1.3`. Como a pilha adota só TLS 1.3, o item 1.4 deve configurar `ssl_protocols TLSv1.3` explicitamente.
- **Limite de taxa: 429 não é o padrão.** A página do `ngx_http_limit_req_module` informa que `limit_req_status` responde 503 por padrão. Para manter o 429 das definições comuns, o item 1.4 deve configurar `limit_req_status 429`.
- **Limite de corpo.** A página do `ngx_http_core_module` confirma que `client_max_body_size` responde 413 e que o padrão é 1 MB.
