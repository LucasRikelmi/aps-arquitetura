# 1.9 — PostgreSQL em execução

**Item:** 1.9 do M1 · **Escopo:** instância local usada pelo projeto (`rh_db`).

**Normas de referência:** ISO/IEC 25010, característica de segurança (confidencialidade e controle de acesso). Referência de estrutura, não certificação.

## Configuração aplicada

| Item | Valor | Motivo |
|---|---|---|
| Versão | PostgreSQL 17 (Windows, serviço `postgresql-x64-17`) | Versão instalada na máquina |
| Base | `rh_db`, schema `rh` | Ver `db/001_ddl_recorte.sql` |
| Porta | 5432 | Padrão, conforme K8 |
| Escuta | `listen_addresses = 'localhost'` (só `127.0.0.1` e `::1`) | Escuta apenas local, conforme o item 1.9 |
| Papel da aplicação | `rh_app`, com login e senha, sem superusuário | Privilégio mínimo |
| Papel de manutenção | `rh_manutencao`, sem login | Execução das rotinas de retenção (ver 1.7) |

## Como reproduzir

1. Em `postgresql.conf`, definir `listen_addresses = 'localhost'`. Reiniciar o serviço.
2. Criar a base: `CREATE DATABASE rh_db;`.
3. Criar o papel da aplicação com login. A senha **não** vai para o repositório:
   `CREATE ROLE rh_app LOGIN PASSWORD '<senha>';`
4. Aplicar os scripts na ordem: `001`, `003`, `002`, `004`, `005`, `006`.
5. Conferir a escuta: `Get-NetTCPConnection -State Listen -LocalPort 5432` deve mostrar só `127.0.0.1` e `::1`.

## Segredos

- As senhas não estão no repositório. O agendador lê a senha do arquivo `pgpass.conf` do perfil do usuário.
- A senha de demonstração do seed (`Demo@2026`) é pública e só serve para a base de demonstração. Não reutilizar.
